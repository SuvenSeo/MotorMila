# Android buyer release candidates

The opt-in track uses the normal `directRelease` package (`lk.motormila.app`) and release certificate so a tester can install over the previous direct release without erasing their shortlist. It does **not** replace the public install page, stable manifest or GitHub latest link.

1. Set a strictly increasing `versionCode` and a `versionName` such as `2.0.0-rc1`. Build from the reviewed commit on the candidate branch, using a manual dispatch of **Android Release**. Verify that the workflow on **that ref** disables publication, R2 upload and manifest pushes on manual runs. Never use an `android-v*` tag for an RC.
2. Download the `motormila-apk` Actions artifact. Verify the SHA-256 release signing certificate matches a digest-verified earlier official APK using `apksigner verify --print-certs`. Record the APK's own SHA-256, package, version name and code separately. A debug/preview signature is not a substitute for this step.
3. On a disposable Android emulator with a private ADB server, run `python scripts/android_rc_smoke.py --help` for the exact inputs. Gate a fresh install on two cold launches: Home semantics present, package still resumed and alive, and no package crash. Exercise guest search → detail → save → force-stop → saved vehicle. Try a listing without a defensible valuation and a draft search the alerts service cannot reproduce. An unsuccessful request must never look like a successful alert.
4. On the same disposable device, install the verified previous stable build, save a vehicle as a guest, and upgrade without clearing data. Pass `--upgrade-from` for the initial version. Confirm the saved item still opens. Physical OEM testing and authenticated delivery are separate results, not implied by these checks.
5. Only after checks pass, publish **the tested bytes** as a GitHub prerelease on an `android-test-*` tag that points at the same commit. Pass `--latest=false`. Download via its public asset URL into a fresh path; re-hash and match the verified APK. Recheck GitHub latest, `/app/latest-release.json`, and `/api/v1/releases/app` to ensure the test build hasn't entered the stable channel.

For withdrawal, restore both manifests to the *same previously verified signed stable asset*, do not ask installed users to downgrade or uninstall, and wait for both the website and the API to actually return the safe version. The API caches the site manifest independently. Never suggest clearing storage to make an upgrade pass.
